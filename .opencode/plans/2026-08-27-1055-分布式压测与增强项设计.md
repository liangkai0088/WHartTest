# 分布式压测调度引擎 + 增强项设计

> Goal: 补齐唯一骨干缺口「跨主机分布式施压」（本机以协议+单测验证，真实跨机留待 Docker/多机），并落地增强项：门禁下游展示、自愈成功率趋势、执行进度轮询兜底。

## 约束与边界（必须确认后编码）
- 本机无 Django 依赖、无第二节点、Docker 外网不可达 → 分布式调度以「协议端点真实可调 + 纯逻辑/单测」验证为主，跨机端到端留待外网恢复。
- 单机闭环保障：**未绑定节点或节点离线时自动回退本地执行**（现状路径不变），保证功能始终可视可用。
- 复用：`push_execution_update`、`render_locustfile`、`PerfTestNode` / `PerfTestExecution` 既有建模。

## 分布式压测引擎设计（D1=A、D2=A）

### 状态与模型
- 复用 `PerfTestNode`（不新增字段）：在线节点表示可接单。`PerfTestExecution.node` 已记录绑定节点。
- `PerfTestExecution.status` 复用现有枚举（`running` 即已认领；`pending` 即待认领）。

### 调度协议（pull，worker 端主动）
新增 `PerfTestNodeViewSet` actions（`perf_test/views.py`）：

1. `POST /api/perf-test/nodes/<node_id>/claim/`
   - master：取 `execution = PerfTestExecution.objects.filter(node=node_id, status='pending').order_by('created_at').first()`
   - 原子认领：`update(status='running') WHERE id=execution.id AND status='pending'`（防多 worker 并发抢同一任务；`execution.start()` 落 started_at）
   - 无任务 → `{has_task: False}`；有任务 → `{has_task: True, task:{execution_id, locustfile, host, users, spawn_rate, duration}}`
   - 任务内容由 master `render_locustfile` 渲染下发（远端无 DB，不重复渲染）。

2. `POST /api/perf-test/nodes/<node_id>/progress/`  `{execution_id, progress, rps, users}`
   - 更新 `execution.progress` + `push_execution_update`（复用现有 WS 推送）。

3. `POST /api/perf-test/nodes/<node_id>/report/`  `{execution_id, stats, series, error?}`
   - 成功：`update_or_create(PerfTestReport, execution=...)` + `execution.complete()` + `_dispatch_diagnosis(report)`。
   - 失败：`execution.fail(error)`。

### worker 脚本（可独立部署，`perf_test/node_worker.py`）
- `python perf_test/node_worker.py --node-id N --interval 5`
- 循环：`claim` → 无任务则 sleep；有任务则起 Locust（复用 `_build_command`、`_prepare_workdir` 思路）→ 周期 `progress` → 结束 `report`。
- 亦可直接用命令行按协议对接任意施压机（协议 HTTP 化，不强依赖 Django-run script）。

### master 侧入口适配（`perf_test/runner.py` / `views.py`）
- `_dispatch_execution`：`plan.node` 存在且 `node.status=='online'` → 走分布式路径（`status='pending'`，不本地跑，等 worker 认领）；否则回退现状本地执行。
- `run_perf_test(execution_id)`：仅本地执行；已认领（distributed）的执行不在此处理，避免双重执行。加守卫：若 `execution.node` 非空且状态经 claim 置 running，则直接返回（防本地误执行）。
- 新增配置 `PERF_DISTRIBUTED_ENABLED`（默认 True）。

### 单机验证
- 单测（纯逻辑）：`claim` 原子认领、无任务分支、`progress`/`report` 落库、`report` 状态流转、节点离线回退本地。
- curl 手测三端点（状态流转可视）。

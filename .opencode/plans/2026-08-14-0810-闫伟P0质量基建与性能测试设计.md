# 闫伟 P0 任务设计方案（质量基建 + 性能测试）

## Goal

完成 AgentQA（原 WHartTest）后续规划中闫伟名下 5 个 P0 任务：
1. AI 压测编排与诊断（战略方向）
2. 全链路代码覆盖率透视（战略方向）
3. 新一代现代化性能测试平台（战略方向）
4. 知识库图片提取 + 多模态向量检索增强（CE 缺口）
5. 自动化测试一键生成与自愈（战略方向）

## Constraints & Preferences（已确认）

- 压测引擎：**Locust**（与 Django 同栈、分布式、复用请求构造逻辑）
- 覆盖率首期：**仅自动化测试**（手工功能覆盖率需插桩探针，延后）
- 设计文档：写入 `.opencode/plans/`
- 排期：按依赖最优（阶段1 并行 → 阶段2 → 阶段3）

## 任务 1+3：性能测试平台（perf_test App）

### 数据模型
- `PerfTestScenario`：场景（name、source ∈ interface/swagger/har/ai、project FK、locustfile 渲染缓存）
- `PerfTestRequest`：请求模板（method/url/headers/params/body、weight、动态参数、断言）
- `PerfTestPlan`：负载模型（users、ramp_up、duration、think_time、target_qps）
- `PerfTestExecution`：执行记录（状态机 pending→running→completed/failed、进度游标）
- `PerfTestReport`：聚合报告（P50/P95/P99、QPS/TPS、错误率、RPS 时序、瓶颈快照）
- `PerfTestNode`：分布式施压节点（心跳、资源使用）

### 脚本生成（四来源 → 统一 Locust 脚本模板）
1. 接口定义：复用 `ApiInterface.get_interface_data()`（api_interfaces/models.py:168）
2. Swagger/OpenAPI：新建导入器解析 JSON（api_sync 非 Swagger，需新写）
3. HAR：解析 HAR entries → 请求模板
4. AI 编排（任务1）：LLM 理解业务链路 → 生成带动态参数/条件逻辑的脚本

### 执行与指标
- Celery 调度 → 容器化 Locust runner（docker 或 worker 内 gevent 进程）
- 复用 `response_time_ms` 采集（httprunner/client.py:375）
- 实时大盘：复用现有 WebSocket 基建推送 QPS/RT/错误率/资源使用
- AI 诊断：压测报告 → LLM → 结构化诊断（瓶颈 + 连接池/索引/缓存建议）

### 分期
- 3-1 基建：引擎接入 + 三来源 + 负载模型 + 指标聚合 + 大盘
- 3-2 AI：LLM 脚本编排 + AI 诊断 + 场景模板库（秒杀/登录/支付）

## 任务 2：代码覆盖率透视（coverage App）

### 数据模型
- `CoverageReport`：上报批次（被测系统标识、测试类型、关联测试执行、格式）
- `CoverageFile`：文件级（路径、行/分支覆盖率）
- `CoverageLine`：行级（行号、命中次数）→ 存 JSONField
- `CoverageDelta`：增量覆盖率（关联 commit）

### 采集
- 统一上报 API `POST /api/coverage/reports/`
- 解析器支持 Cobertura XML（coverage.py/Jacoco）、LCOV（Istanbul）
- 被测系统侧集成插桩工具（WHartTest 提供 SDK 简化接入）

### 可视化
- 仪表盘：文件级/方法级/行级
- 增量覆盖率：每次提交覆盖变化
- 覆盖率门禁：低于阈值阻断合并（接口预留，对接张晋文插件域）

- 知识库曾加过 DocumentImage（migration 0014/0015）后删除（0017），默认嵌入模型已切 qwen3-vl-emb-2b，`embed_image()` 无调用方——说明当时图片提取未实现，改用 VL 模型是替代方案
- requirements 模块占位符格式 `docimg://img_XXX` 与 knowledge 前端期望 `{{IMAGE:N}}` 不一致，knowledge 侧必须用 `{{IMAGE:N}}`（前端 DocumentDetailModal 用 image_index 匹配）
- 前端知识库图片 UI 是死代码（DocumentDetailModal 解析 `{{IMAGE:N}}`、KnowledgeBaseDetail 渲染 `metadata.content_type==='image'` + `resolved_images`），后端补齐数据即生效
- Agent Loop 是「单 Agent + 中间件」模式（create_agent），非手写多节点 StateGraph；LLM 配置为全局单模型（LLMConfig 唯一激活），无模块级配置
- httprunner 是 vendored HttpRunner 3.x，同步串行 requests，压测必须另起 Locust，不能改造它

### 阶段1 实现要点（本轮产出，新会话续接需知）
- **knowledge**：`DocumentImage` 用 `image_index`(从0起) 匹配占位符，非 requirements 的 `image_id` 字符串；`_save_image` 用 `document.images.count()` 作递增索引（process_document 先 `_clear_document_images` 保证从0）；图片接口 `get_image` 用 `authentication_classes=[]` 公开访问（`<img>` 无法带 token，与 requirements 一致）；`_resolve_images` 批量查询避免循环内查询
- **落库工具**：`save_ui_automation_case(case_json)` 单 JSON 参数一次性落库；ope_value 约定 dict（`{"text":...}`/`{"url":...}`），consumer.py:1153 按 text>value>timeout>url>key>expected 提取 input_value；工具在 `get_builtin_tools` 注册后经 agent_loop_view.py:978 自动加载
- **code_coverage**：App 命名避开 `coverage`(Python 包冲突)；解析器兼容 coverage.py(`hits`) 与 Jacoco(`ci/mi`) 两种 Cobertura line 格式；行级明细存 CoverageFile.lines_detail JSONField；上报接口 `POST /api/code-coverage/reports/`(multipart file+project_id)

### 阶段2 实现要点（本轮产出，新会话续接需知）
- **执行引擎用 subprocess 而非编程式 LocalRunner**：`runner.py` 渲染 locustfile 写临时目录 `/tmp/perf_test/<execution_id>/`，`Popen([locust, -f, ..., --headless, --users, --spawn-rate, --run-time, --csv, --csv-full-history, --only-summary])`；隔离在独立进程避免 gevent monkey-patch 污染 Celery worker，且可用 `--csv` 拿到标准统计
- **指标聚合靠解析 locust CSV**（非自己算百分位）：`services.parse_locust_stats_csv` 读 `result_stats.csv` 的 Aggregated 行（注意：Locust CSV 中 Aggregated 行的 `Type` 为空、`Name` 为 "Aggregated"，必须按 Name 匹配）；`parse_locust_history_csv` 读 `result_stats_history.csv` 得 RPS 时序
- **进度/大盘**：task 内 `_run_and_monitor` 循环 poll 子进程 + 每 1s 读 history csv 尾部推 WebSocket（group 名 `perf_test_execution_<id>`，type `perf_test.update`→consumer 方法 `perf_test_update`）；asgi.py 已合并 `ui_ws_patterns + perf_ws_patterns`
- **关键陷阱**：Django OneToOne 反向不存在时抛 `DoesNotExist`（非返回 None），serializer 里 `plan`/`report` 必须用 try/except 或 SerializerMethodField，不能直接 `getattr(obj,'plan',None)`
- **依赖**：requirements.txt 加了 `locust>=2.20`；Celery 任务 `perf_test.tasks.run_perf_test` 走默认 `celery` 队列（worker 已监听 `-Q celery,task_center`）
- **路由**：REST 全局注册 `/api/perf-test/{scenarios|requests|plans|executions|reports|nodes}/`；一键执行走 `POST /api/perf-test/scenarios/<id>/execute/`；WebSocket `/ws/perf-test/<execution_id>/`
- **target_qps 限流**：阶段3-1 已实现——渲染时传 `target_qps`+`users` 用 `constant_pacing(users/target_qps)` 近似限流（非精确 LoadTestShape）
- `stop` 仅 revoke celery + 标记 canceled，locust 子进程靠 --run-time 自行退出
- **未做**：分布式多节点调度（PerfTestNode 已建模型未接入执行）
